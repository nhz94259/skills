# API / 能力文档规范

## 文件位置

- 能力索引：`docs/api/README.md`
- 单能力文档：`docs/api/{capability-name}.md`
- 接口变更说明：`docs/api/{capability-name}-changes.md`（按需）

`docs/api/` 用于长期沉淀跨需求复用的接口与能力说明。它不是当前需求的临时设计草稿；当前需求仍以 `docs/dev/sdd/design.md` 为事实源。设计中形成稳定接口、协议或模块能力后，再同步沉淀到 `docs/api/`。

## 写作目标

API 文档必须让用户和其他 agent 不读全仓库也能快速理解：

- 从哪些入口可以调用这项能力。
- 这项能力完整支持什么、不支持什么。
- 输入、输出、字段、错误和兼容边界是什么。
- 请求进入系统后经过哪些模块、函数或服务。
- 表面接口之外有哪些行为细节、默认值、降级和限制。
- 后续扩展或接入时应该改哪些位置、验证什么。

> 原则：从入口视角写能力全貌，不只罗列 endpoint 或字段。

## 推荐阅读结构

| 阅读区块 | Markdown 表达 | 目的 |
|----------|---------------|------|
| 首屏摘要 | 标题 + 文档信息表 + 2-3 句话摘要 | 先说明能力、状态、读者入口 |
| 能力概述 | 说明 + 能力矩阵 | 让读者知道仓库已经具备什么 |
| 入口总览 | 表格 | 从用户、Agent、API、IPC、SDK 或内部模块入口定位能力 |
| 调用链 / 数据流 | ASCII、Mermaid 或步骤表 | 解释请求从入口到落地的完整路径 |
| 接口 / 协议规范 | 类型、字段表、示例 | 固化可调用契约 |
| 行为细节 | 表格或分节 | 记录默认值、格式化、状态流转、降级、副作用 |
| 完整示例 | 请求 / 响应 / 调用片段 | 让其他 agent 可以直接复用 |
| 集成指南 | 按调用方分节 | 说明前端、后端、Agent、测试如何接入 |
| 扩展方法 | 步骤表 | 新增能力时知道改哪里 |
| 约束与限制 | 矩阵表 | 暴露性能、兼容、安全和边界条件 |
| 版本历史 | 表格 | 记录协议演进 |

## 编写要点

### 入口视角优先

每份 API 文档都必须有“入口总览”。入口可以是：

- HTTP / GraphQL endpoint
- IPC channel
- SDK 函数
- CLI 命令
- Webhook / callback
- 内部模块导出函数
- Agent 输出协议
- 前端组件 props / 事件

入口总览不是文件列表。它要回答“谁从哪里进来、能触发什么能力、落到哪个实现”。

### 能力矩阵优先于接口清单

接口清单只能说明“有什么接口”，能力矩阵要说明“仓库已经能做什么”。对于用户和其他 agent，能力矩阵通常比 endpoint 表更重要。

建议至少包含：

| 能力 | 支持情况 | 入口 | 关键限制 | 示例章节 |
|------|----------|------|----------|----------|

### 行为细节必须沉淀

以下内容不能只留在代码里：

- 默认值、自动补全、自动格式化。
- 分页、排序、截断、聚合、去重。
- 状态流转、异步任务、重试、缓存。
- 未知字段、未知类型、空数据、脏数据的处理。
- 鉴权、租户、权限和敏感字段边界。
- 降级策略、兼容策略、错误码映射。
- 性能上限、数据量建议、超时和资源限制。

### 字段约束要可验证

请求和响应字段不要只写类型。还要写：

- 是否必填。
- 默认值。
- 枚举范围。
- 格式要求。
- 单位。
- 空值行为。
- 向前 / 向后兼容方式。
- 校验失败时的行为。

### 调用链要能回到代码

调用链可以用 ASCII、Mermaid 或步骤表，但必须包含文件路径、函数名或模块名。不要只写“前端调用后端”“服务查询数据库”这类抽象描述。

最小步骤表：

| 步骤 | 组件 / 模块 | 文件 / 函数 | 行为 | 状态 |
|------|-------------|-------------|------|------|

### 示例要完整可复制

示例应覆盖：

- 最小合法输入。
- 推荐完整输入。
- 典型成功响应。
- 关键错误或降级响应。
- Agent / SDK / 前端使用片段（按能力需要）。

## 与其他文档的边界

| 文档 | 职责 | 不应该做 |
|------|------|----------|
| `docs/dev/sdd/design.md` | 当前需求的正式设计事实源 | 不长期承担稳定 API 索引 |
| `docs/api/` | 长期维护的接口、协议和能力全貌 | 不记录临时讨论和未确认方案 |
| `docs/dev/research/` | 调研、对比、候选方案 | 不作为实现契约 |
| `docs/knowledge/` | 不易腐化的长期知识 | 不放易随版本变化的字段细节 |

## 评审清单

| 检查项 | 要求 |
|--------|------|
| 文档信息 | 有摘要、状态、版本和事实源 |
| 能力矩阵 | 能说明仓库支持的能力全貌 |
| 入口总览 | 覆盖用户、Agent、API、IPC、SDK 或内部模块入口 |
| 调用链 | 从入口到落地，且能映射到真实文件 / 函数 |
| 字段约束 | 接口字段包含类型、必填、默认值、约束和说明 |
| 错误与边界 | 记录错误、降级、兼容、副作用和权限边界 |
| 示例 | 有完整可复制示例 |
| 集成与扩展 | 有集成指南和扩展方法 |
| 限制与历史 | 有约束限制和版本历史 |
| 同步关系 | 当前需求设计中的稳定接口已同步到 `docs/api/` |
